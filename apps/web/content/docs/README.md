# 文档目录约定

这个目录是文档站（`/docs`）的唯一内容来源。它刻意独立于数据库与后台 CMS：

- 文档是**版本控制里的文件**，git 历史就是发布历史；
- 新增或修改一篇文档**不需要**动数据库、不需要登录后台、不需要跑迁移；
- 页面的侧栏、上一页/下一页都从文件的 frontmatter 推导，没有第二份索引文件。

## 新增一篇

1. 在本目录放一个 `.md` 文件，文件名（不含扩展名）就是 slug，例如 `backup.md` → `/docs/backup`；
2. 写 frontmatter：

   ```yaml
   ---
   title: 备份与恢复 # 必填，≤99 字
   description: 一句话说明。 # 可选，显示在索引与页头
   section: 运维 # 可选，侧栏分组；省略归入「入门」
   order: 30 # 侧栏与上一篇/下一篇的排序，数字小的在前
   updatedAt: 2026-10-21 # 可选
   ---
   ```

3. 运行 `pnpm run typegen`（或 `pnpm --filter @hataraku/web content`）让 Velite 重新收集；
4. 提交。没有第 5 步。

## 正文能力

- 标题（`##` / `###`）会自动获得锚点，右侧 TOC 与锚点来自同一次渲染；
- 代码块由 Shiki 双主题高亮，右上角有复制按钮；
- 容器提示使用指令语法：

  ```markdown
  :::note 可选标题
  内容，支持 Markdown。
  :::
  ```

  可用类型：`note`、`tip`、`warning`、`danger`。指令内外都可以正常写代码块；代码块里的 `:::`
  不会被当作指令。

## 不做什么

- 不接数据库或后台编辑器：文档的生命周期属于仓库，文章的生命周期属于 CMS，两者不要混；
- 不引入 KaTeX / Mermaid（本轮范围外）；真有公式或图需求时先讨论依赖，再落地。
